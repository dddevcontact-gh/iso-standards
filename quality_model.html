Quality model

Relevant standards:

  • 25010 (product quality)
  • 25012 (data quality)
  • 25019 (quality in use)
  • 25059 (AI systems quality)


One of the big issues is having vague methods to define how good a product / component is. To fix this, quality characteristics were defined in ISO/IEC 25010, and each has their own sub-characteristics to get an extremely specific definition for quality.


For example, someone could develop an app for a town to monitor certain parts, such as carbon dioxide and traffic levels (where have we seen this before?). To check whether it’s up to quality standards, they need to check the product against each characteristic. We will use performance efficiency as an example. It has three sub-characteristics: Time behaviour, resource utilization and capacity.


The product is then checked against each of these sub-characteristics. These are defined fully in the actual 25010 standard, found in the links at the top. To check against the sub-characteristics, goals are set to see if it passes (such as for time behaviour, to see if it keeps to required response time / throughput rates under working conditions). It’s important to note that the actual requirement can differ depending on the implementation of the system and its goals.


Other standards under 2501n are similar, but with different focuses. The one described above, 25010, focuses on software. 25012 describes data quality, 25019 describes quality in use, and 25059 describes AI systems quality (a newer one acting as an extension, which is why it doesn’t fit the same number pattern as the others).
